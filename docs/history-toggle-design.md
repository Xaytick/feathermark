# 编辑历史开关 — 重新设计方案

> 状态：设计稿，未实现。本文是对用户上一版需求描述的**专业重构**，不是照单全收。
> 组织：需求说明 / 状态规则 / 边界情况 / 验收标准。

---

## 〇、首先：为什么重写需求

用户原描述的核心要求是「文档目录非 Git 时自动 `git init`，把历史写进用户仓库的独立 ref」。
我认为这个要求有两个内在缺陷，应先解决再谈开关：

**缺陷 1：与已确立的设计原则冲突。**
v0.4.38 定下的核心卖点是「不污染用户仓库」——历史只写 `refs/feathermark/*`，
不动 HEAD、不建 commit、不改配置。但「自动 `git init` 非 Git 目录」恰恰把一个普通文档目录
变成了 Git 仓库：用户下次 `git status` 会看到整目录未跟踪文件，云同步目录会同步 `.git/`，
用户可能困惑或误删。**用 git 作为存储引擎 ≠ 必须动用户目录。**

**缺陷 2：用户仓库不是"我们的"，生命周期不受控。**
用户可能 `git gc --prune`、`filter-branch`、删除 `.git`、换机器不克隆历史、把目录加进大仓库……
我们的历史会随用户的 git 操作一起消失或被改写。一个"编辑历史"功能不该把数据主权交给外部。

**重构方案：历史存进应用自己的私有 Git 仓库（App Data 下），永不触碰用户目录和用户仓库。**
仍然用 git 做存储引擎（内容寻址、delta 压缩、成熟 diff 全保留），但把 git 当作"数据库"而非"用户工作区"。
技术上已验证：私有仓库无 HEAD 也能写 ref/commit，`git log refs/...` 照常可用，起步 108K。

这个改动顺带消灭了原需求里几乎所有边界复杂度：嵌套仓库、多文档目录、自动 init 副作用、
关闭时"不能碰用户仓库"——因为**我们从头到尾就不接触用户仓库**。

## 一、需求说明

### 1.1 目标

给编辑历史加一个总开关：开启时用私有 Git 仓库记录文档编辑版本；关闭时不再记录。
全程不检测、不初始化、不读取用户的任何 Git 仓库。

### 1.2 设置项

| 项 | 值 |
|---|---|
| 存储键 | `prefs.historyEnabled`（`feathermark.prefs.v1` 内，随偏好持久化/重置） |
| 显示名称 | 中「记录编辑历史」/ 英「Track edit history」 |
| 位置 | 设置 → 编辑，复用现有 `row(..., toggle(...))`，与自动换行同组 |
| **默认值** | **开启（true）** |
| 说明文案 | 开启后，AI 编辑会保存可回溯的历史版本（存在应用数据目录，不影响你的 Git 仓库）。关闭后不再记录新版本，已有历史保留。 |

**为何默认开启**：重构后开启无任何目录副作用（不 init、不检测用户仓库），
默认开能让功能真正被用上；若默认关，绝大多数用户永远不会发现它。

### 1.3 关键定义

- **历史仓库**：`{app_data_dir}/history/`，一个专用的 git 仓库，由应用首次需要时自动创建。
  - 与现有 `ai-config.json` 同在 App Data 目录，符合项目"密钥/状态存本机"的既有约定。
  - 用户可在设置里看到这个路径（便于高级用户自行 `git log` 查看）。
- **文档键（docKey）**：文档的稳定标识，用于区分不同文档的历史。
  - 有 `tab.path`：用规范化的绝对路径（统一分隔符、去 `..`）。
  - 未保存文档：用 `untitled/<name>`；另存为后切换到路径键（旧键历史保留但不再写入）。
  - 每个 docKey 一条 ref：`refs/feathermark/<hash(docKey)>`，用 hash 避开路径字符与长度问题。
- **历史数据**：仅指私有仓库中的 ref/commit/blob。用户的工作区、`.git`、提交、配置**完全不在我们的作用域内**。

## 二、状态规则

### 2.1 开关 × 文档状态矩阵

| 开关 | 文档状态 | 行为 |
|---|---|---|
| 开 | 已保存 | 写入私有仓库对应 docKey 的 ref（无则创建仓库/ref） |
| 开 | 未保存 | 写入 `untitled/<name>` 的 ref（不需要任何目录，直接可记） |
| 开 | 私有仓库创建失败 | 不记录，toast 提示，编辑照常 |
| 关 | 任意 | 不调用任何历史命令，不创建/打开私有仓库，不写 ref |

注意：开关状态与"文档所在目录是不是 git 仓库"**完全无关**——我们不检测、不关心。

### 2.2 开关切换

- **开 → 关**：后续写回不记录；不删除任何历史；不弹确认（可逆轻量偏好）。
- **关 → 开**：下一次写回起记录，接上原有 ref 链；不补记关闭期间的编辑（明确为预期行为，写入文档）。
- 切换只改一个布尔偏好，无文件系统动作。

### 2.3 已有历史的保留与可见性

| 维度 | 规则 |
|---|---|
| 数据保留 | 关闭永不删除私有仓库或任何 ref |
| 面板可见 | 关闭后面板仍可打开、看 diff、另存文件 |
| 恢复操作 | 关闭时恢复按钮**禁用**（恢复会写"恢复点"版本，与"不记录"冲突）；开启后自动可用 |
| 清空操作 | 关闭时仍可用（显式用户动作），需二次确认 |
| 外部可见 | 历史是标准 git 仓库，用户可在设置显示的路径下用 `git log refs/feathermark/...` 查看 |

### 2.4 提交记录范围与说明规则

- **产生**：私有仓库内，每个 docKey 一条 ref，每次编辑追加一个 commit。
- **不产生**：不动任何用户仓库；私有仓库自身允许无 HEAD（不建初始提交）。
- **message**：`feathermark: <模板名/来源> · YYYY-MM-DD HH:MM`，可选 `feathermark-meta` trailer（沿用现有格式）。
- **身份**：固定 `FeatherMark <feathermark@local>`。
- **内容**：每个 commit 的 tree 里放 `document.md`（版本全文），沿用现有结构，`git show <id>:document.md` 可取回。

## 三、边界情况

### 3.1 嵌套仓库 / 多文档目录

**不再是问题**：我们不 discover 用户目录，全部历史在应用私有仓库按 docKey 隔离。
- 两个不同仓库里的同名文档：绝对路径不同 → docKey 不同 → 历史独立。
- 一个目录下多个文档：各自 ref，互不干扰。

### 3.2 文档重命名 / 移动

docKey 变（路径变）→ 旧 ref 保留但不再关联，新路径从零开始。
本轮不做迁移；这是已知限制，写入文档说明。

### 3.3 未保存 / 临时文档

未保存时用 `untitled/<name>` 键，**可以直接记录**（这是重构带来的额外好处——
原方案要求"先保存到非 git 目录再 init"，现在完全不需要）。另存为后换新键。

### 3.4 私有仓库异常

| 情形 | 提示 | 处理 |
|---|---|---|
| App Data 不可写 / 磁盘满 | 「无法创建历史存储：{原因}」 | 不记录，编辑照常；同一错误 30 秒内节流 |
| 仓库损坏（对象/ref 异常） | 「历史存储不可用：{原因}」 | 不覆盖、不重建；提示用户可在设置里"重置历史存储" |
| 用户手动删除 history 目录 | 下次开启时自动重建空仓库 | 不提示（等价于全新开始） |

### 3.5 隐私与清理

- 历史含文档全文，存本机 App Data；设置面板显示路径，用户可自行删除。
- 提供"清空全部历史"入口（删除私有仓库内所有 feathermark ref，不删仓库本身）。
- 应用卸载时随 App Data 一起清理（遵循系统惯例）。

## 四、验收标准

1. **默认值**：全新安装 `prefs.historyEnabled === true`，设置里开关为开。
2. **无目录副作用（核心）**：在非 Git 目录新建保存文档并 AI 编辑 →
   **该目录不出现 `.git/`**，用户 `git status`/`git log` 不存在的目录状态不变。
3. **记录成功**：AI 编辑后，私有仓库 `git log refs/feathermark/<hash>` 有新 commit；
   `git show <id>:document.md` 等于写入的全文。
4. **未保存文档**：未保存的新文档做 AI 编辑也能记录历史（untitled 键）。
5. **关闭**：切换后 AI 编辑 → 私有仓库不新增任何 ref/commit；已有历史字节不变。
6. **历史保留与只读**：关闭后面板可看 diff、可另存；恢复按钮禁用；再开启后恢复可用且接上原链。
7. **用户仓库零接触**：在已有 Git 仓库工作 → 编辑前后用户仓库的 `.git` 目录做 md5 比对完全一致。
8. **多文档/嵌套**：不同仓库的同名文档、同目录多文档历史互不串。
9. **失败不阻塞**：把 App Data 设为只读 → 出现明确 toast，文档编辑与保存照常。
10. **外部可查**：按设置显示路径进入私有仓库，`git log refs/feathermark/<hash>` 能看到完整历史。

## 附：与用户原描述的差异（供决策）

| 用户原要求 | 本方案 | 理由 |
|---|---|---|
| 非 Git 目录自动 `git init` | 不 init 用户目录，用 App Data 私有仓库 | 消除目录副作用，数据主权归应用 |
| 历史写用户仓库独立 ref | 写私有仓库 ref | 不再依赖用户仓库生命周期 |
| 关闭时不动用户仓库 | 天然满足（从不接触） | 从设计上消除风险，不靠约束 |
| 文档所在目录为基准 | 文档绝对路径为 docKey | 不需目录即可记录，未保存文档也能记 |
| 嵌套/多文档边界 | 复杂度消失 | 统一按 docKey 隔离 |

如果用户坚持"历史必须放进用户自己的仓库以便外部查看"，
可在本方案上加一个**高级设置** `historyStorage: private|repo`（默认 private），
选 repo 时才退回 v0.4.38 的独立 ref 行为。本方案默认不含此项，避免过度设计。
